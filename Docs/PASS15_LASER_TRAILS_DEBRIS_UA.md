# PASS15: активний лазер, яскравий шлейф і записане руйнування

18.11.2026, Unity 6000.0.58f2, Windows x64.

Сцена: Assets/Scenes/Escape_Zone003_PC_RESTORED_PASS15.unity.
Збірка: Builds/Windows-PASS15/Escape-PASS15.exe.

## Виправлення помилок PASS14

У PASS14 перевірено декодовану UFOLaser-маску, але не активний промінь.
Оригінальний SpriteRenderer #86895 на GO #16824 використовує sprite #705
Laser, який розміщено на ASTC-текстурі #48 HudCheckPointSeparator.
Виправлення лише sprite #676 UFOLaser тому не усувало кольоровий промінь.
Тепер прочитано фактичне посилання, декодовано ASTC 32×2048 і вирізано
оригінальний прямокутник 32×12 з його PPU та pivot. Попередні зображення
не переписані. Нова сцена використовує окремий приватний crop.

Також у native TrailRenderer посилання на матеріал прочитано на 4 байти
раніше: замість material ID отримано external file ID=1. Через це обидва
шлейфи мали димову текстуру й alpha blending. Перевірено native renderer
header: array count на offset 28, file ID на 32, material ID на 36.
Новий прохід повертає material #30 Particles/Additive + RocketTrail для
яскравого сліду, #29 Particles/Alpha Blended + RocketTrailSmoke для ширшого
прозорого. Авторський імпортер PASS14 теж виправлено для майбутніх запусків.
Попередні приватні PASS14 JSON, матеріали та сцена залишені як були.

## Руйнування конструкцій

Дві PhysicalGroup у Zone003 мають simulationMode=1 (playback), а їхні
PositionsRecorder — record=false. В оригінальному runtime Rigidbody цих
частин знищуються, а траєкторії відтворюються із PositionsRecords assets.
Тому застосовувати довільний AddExplosionForce до цих конструкцій було б
підміною підтвердженої механіки.

З приватних assets #870 та #869 прочитано відповідно 8 і 40 треків.
Кожен має шість AnimationCurve: local X/Y та quaternion X/Y/Z/W, з
оригінальними time/value/inTangent/outTangent і clamp wrap modes.
Порядок transforms береться з recordInput конкретного PositionsRecorder.
Під час playback local Z стає 0, як у Vector2→Vector3 оригінального методу.

Сигнали play взято з оригінального anim_Zone003: перша група починається
на 14.416667 с часу зони, друга — на 20.616667 с і зупиняється на
25.866667 с. Успадкований годинник зони працює зі швидкістю 1.25.
Реалізація інтегрує ділянки gate=true, семплює запис і зберігає результат
після stop; до першого play повертає початкові трансформи. Пауза, seek,
reset і завершення використовують той самий годинник сцени.

Оригінальний PositionsRecorder.Playback спочатку семплює recordTime,
потім додає deltaTime. Нова оцінка за безперервним часом може випереджати
цей дискретний порядок менш ніж на один кадр. Точне відтворення порядку
оновлень Unity4 залишається окремим питанням; самі криві не підганялися.
RadialForce для інших незаписаних фізичних об'єктів ще не перенесено.

## Перевірки

- Play Mode справді просував кадри. Для всіх 48 частин перевірено 121
  позу на всій зоні; Unity AnimationCurve порівняно з незалежною формулою
  Hermite. Максимальна похибка local position — 0.000031 одиниці;
  quaternion перевірено окремо. Після запуску записів рухаються всі 48.
- Активний лазер знято на 21.2 с часу зони. Локальний знімок
  Reports/pass15-active-laser.png перевірений візуально: білий промінь
  проходить крізь розірвану конструкцію, частини розлітаються.
- Обидва шлейфи генерують реальні native vertices. Знято разом та
  окремо, перевірено текстури й blend modes. На pass15-trails-both.png
  видно яскравий внутрішній слід і ширший прозорий зовнішній.
- Дані відновлення й кадри залишаються приватними у RecoveredVisualsPass15Local
  і Reports/pass15-*. Старі сцени перевіряються SHA256 перед комітом.
- Windows build і регресії 30/60/144 FPS перевіряються окремим Player-аудитом.

## Наступні невідновлені системи

Притягання людей, круглі маркери та лінії до дверей, анімації й посадка
ще не реалізовані. Також немає атмосферного диму/туману/пожеж і нафти.
Дослідження показало, що Zone003 містить старі EllipsoidParticleEmitter,
ParticleAnimator і ParticleRenderer, а не лише сучасні ParticleSystem.
Знайдені джерела PSL-LongTrailSmoke, PSL-AfterDestroyFire та
PSL-AfterDestroySmoke. Їх потрібно переносити з перевіркою старих модулів,
емісії й подій; випадкові ефекти з подібним виглядом не додавалися.

Запуск відновлення: tools/recover_visuals_pass15.py --project з локальним
проєктом, потім EscapeVisualCorrectionPass15.Create. Потрібні приватний
архів і PASS14. Create завжди робить нову сцену; Build збирає базову PASS15.
