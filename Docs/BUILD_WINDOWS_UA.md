# Підготовка відновлення Escape (2015) до Windows

**Стан:** архівний Unity 6 проєкт-основа; **НЕ відновлена гра, що працює**.

## Перевірені дані
- Оригінал в APK: Unity `4.6.5f1`, Mono/C#.
- Є керовані DLL, сирі Unity-ресурси, відновлені PNG/WAV/MP3 та частина ETC2 у KTX.
- Ієрархія `level0`: 34 993 GameObject і 34 993 Transform/RectTransform.
- Зібрано повний індекс об'єктів Unity зі збереженням `path_id`, `offset`, `size`.
- Ассемблерний IL у `RecoverySource/DisassembledIL/` — **не C# вихідний код**.

## Відкрити й побудувати діагностичний Windows EXE
1. Клонуйте репозиторій та імпортуйте приватний архів ZIP через `tools/restore_local_archive.py`, як описано в README.
2. Відкрийте корінь проєкту в Unity Hub, оберіть Unity 6. Unity Hub може запропонувати оновлення/перегенерацію ProjectSettings.
3. Дочекайтеся імпорту локальних PNG та аудіо.
4. У головному меню запустіть `Escape Recovery -> 1 - Rebuild original hierarchy (35k objects)`.
   Це відновить назви, активність, шари, батьківські зв'язки, локальні позиції, повороти, масштаби; збереже `Assets/Scenes/Escape_Structure_RECONSTRUCTED.unity`.
5. Відкрийте сцену (якщо не відкрилася) й перегляньте структуру.
6. Для **тестового, НЕ ігрового** Windows EXE: `Escape Recovery -> 2 - Build Windows x64 scaffold (not playable original)`.
   Вивід: `Builds/Windows/EscapeRecoveryScaffold.exe` на вашому комп'ютері. Потрібен Unity Build Support (Windows).

## Чого тут немає
- Немає оригінальних `.unity`, `.prefab`, `.mat`, `.fbx`, `.meta` з редактора розробника.
- Відтворення GameObject НЕ повертає Renderer, MeshFilter, SpriteRenderer, Material, Animator, Collider та MonoBehaviour. Вони збережені в оригінальних серіалізованих файлах у `RecoverySource/OriginalUnityData/`.
- 12 ETC2 текстур ще не декодовано у PNG; вони збережені в KTX як оригінальні блоки. Розпакувати можна через сумісні інструменти.
- Оригінальні DLL не імпортовано до сучасної Unity 6: вони посилаються на старі Unity API, тому автоматично ігровий код не запуститься.
- Цей проєкт навмисно **не видається за робочу портовану гру**.

## Реальний шлях до працездатної гри
1. **AssetRipper / AssetStudio**: відкрити збережені `.assets`, `level0` та `mainData` у `RecoverySource/OriginalUnityData/` і експортувати рендерери, матеріали, моделі, спрайти, аніматори та сцени.
2. **ILSpy / dnSpyEx**: локально відкрити `Assembly-CSharp.dll` для отримання декомпільованого C# (архів містить також IL-дизасембльований текст і список методів).
3. Вибрати версію Unity: для мінімальних відмінностей спробувати Unity 4.6.5f1 в окремому старому середовищі, для Unity 6 — портувати шейдери й усунути несумісності API/плагінів.
4. Замінити Android-залежні виклики на ПК-логіку вводу й UI та відновити прив'язки компонентів.
5. Зібрати Windows EXE та перевірити рівні й геймплей.

Інструмент імпорту структури постачається лише для збереження прогресу. У вихідних `.assets` є значно більше даних, ніж він наразі відтворює.
